# AGENTS.md - frontend

Веб-панель Invoice Keeper. Общий контекст проекта: [../AGENTS.md](../AGENTS.md), кейс: [../docs/Case.md](../docs/Case.md). Чеклист экранов и их статусы - [plan.md](plan.md).

## Стек

- SPA на React 19 с React Compiler, сборка Vite 8, TypeScript 6 (strict), пакетный менеджер pnpm, Node.js 22.12+.
- UI - Mantine 9 (`@mantine/core`, `dates`, `notifications`, `modals`), иконки - свои компоненты в `src/shared/ui/icons` из набора личного кабинета Aéza (сетка 24 px, линия 1.5, скруглённые концы). Недостающий значок рисуется по тем же правилам через `IconBase`, сторонние наборы иконок не подключаем. Свои стили - CSS-модули (`*.module.css`), тема - `createTheme` Mantine. Tailwind, shadcn/ui и CSS-in-JS не используем.
- Шрифты - Exo 2 (заголовки, крупные суммы) и Inter (остальной текст) из пакетов `@fontsource-variable`, без внешних CDN: установка on-premise может работать без интернета. Моноширинные шрифты не используем.
- Роутинг - TanStack Router, маршруты из файлов. Серверное состояние - TanStack Query. Формы - TanStack Form с валидацией Zod; `@mantine/form` не используем. Состояние интерфейса - Zustand.
- HTTP - axios через клиент, сгенерированный Hey API (`@hey-api/openapi-ts`) из контракта; подмена API в тестах - MSW 2. Вход - аккаунт Aéza через `POST /api/v1/auth/login` backend (ADR-014), токен сессии только в `sessionStorage`.
- Проверки: ESLint (typescript-eslint, правила хуков и React Compiler, плагины TanStack Query и Router), Stylelint, Steiger (FSD), Prettier, Vitest с jsdom и Testing Library.

## Команды

Запускаются из `frontend/`.

- `pnpm install` - установить зависимости.
- `pnpm dev` - dev-сервер на http://localhost:5173. Запросы `/api` он проксирует на `API_PROXY_TARGET`, по умолчанию `http://localhost:8000` (локальный backend). Свой адрес задаётся в `.env.local` (образец - `.env.example`, файл не коммитится) или переменной окружения при запуске, она важнее файла.
- `pnpm build` - проверка типов и production-сборка в `dist/`.
- `pnpm test` / `pnpm test:watch` - тесты Vitest.
- `pnpm lint`, `pnpm lint:styles`, `pnpm lint:fsd`, `pnpm typecheck` - отдельные проверки: ESLint, Stylelint, Steiger, типы.
- `pnpm format` - отформатировать код; `pnpm format:check` - только проверка.
- `pnpm check` - все проверки разом: типы, линтеры, формат, тесты, сборка. Перед завершением задачи она должна проходить.
- `pnpm api:generate` - сгенерировать клиент API в `src/shared/api/generated` из `../backend/api/openapi.yaml` (Hey API, настройки в `openapi-ts.config.ts`). Запускай после каждого изменения контракта и коммить результат: сборка в Docker (`../infra/frontend/Dockerfile`) не видит `../backend` и берёт клиент из репозитория. Руками эти файлы не правятся.

## Архитектура

Feature-Sliced Design 2.1. Правила слоёв, слайсов и импортов - в скилле `feature-sliced-design`; Steiger (`pnpm lint:fsd`) проверяет их автоматически.

- Код лежит в `src/` по слоям FSD. Алиасы строго по слоям: `@app/*`, `@pages/*`, `@widgets/*`, `@features/*`, `@entities/*`, `@shared/*` -> `src/<слой>/*`. Общего алиаса `@/` нет.
- Сначала страницы: код живёт в слайсе страницы `src/pages/<страница>/`, в слои ниже он уходит, только когда нужен нескольким страницам.
- `src/app/main.tsx` - точка входа. `src/app/router.tsx` - создание роутера и его контекст (`queryClient`); во внутренней обёртке роутера (`InnerWrap`) смонтированы `ReauthHost` (лениво грузит окно повторного входа, только когда оно открыто: форма с zod и TanStack Form не попадает в основной бандл) и `SessionWatcher` (сессия пропала - кэш запросов очищается, открывается вход). `src/app/query-client.ts` - клиент запросов.
- Маршруты TanStack Router - файлы в `src/app/routes/`. `__root.tsx` - корневой маршрут без каркаса; `login.tsx` - страница входа (`?redirect=` - куда вернуться); `_authenticated.tsx` - защищённая ветка: без сессии ведёт на вход, при прошедшем сроке ждёт повторного входа, загружает `GET /auth/me`, рисует каркас. Разделы лежат в `_authenticated/`, неизвестный адрес ловит `_authenticated/$.tsx` («Страница не найдена» в каркасе). Файл маршрута только связывает адрес со страницей из `@pages/*`.
- Страницы делятся на свои чанки, хотя маршрут импортирует из `index.ts` страницы (`validate*Search`): так собирает Vite с `"sideEffects": ["**/*.css"]` в `package.json`. Модуль, который нужен только ради побочного эффекта, кроме CSS, не заводим: сборка его выбросит.
- Вход - `src/features/sign-in`: `LoginForm` (пароль, код 2FA, сообщения по кодам ошибок; режим `reauth` - окно повторного входа тем же email) и `ReauthDialog`. Страница входа с панелью бренда - `src/pages/login`. `src/app/routeTree.gen.ts` генерирует плагин роутера при `dev`, `build` и тестах; файл коммитится, руками не правится.
- Каркас «холст и острова» - `src/app/layout`: `AppLayout` (шапка с брендом `ProductBrand` из `@shared/ui/product-brand` - логотип-ссылка на aeza.ru и «Незабудка», кнопкой аккаунта `AccountMenu` с переключателем «Тёмная тема», навигация, нижняя панель значков на телефоне), список разделов `sections.ts` (адрес, название, значок, `adminOnly`) и `useNavMode` (вид навигации по брейкпоинтам `lg` и `sm`). Разделы с `adminOnly` видны только администратору; их маршруты лежат в `_authenticated/_admin/`: `beforeLoad` у `_admin` проверяет роль до загрузчиков разделов, а пользователь вместо страницы видит «Нет доступа» (`errorComponent`, `src/pages/forbidden`). Новый раздел добавляется в `sections.ts` и файлом маршрута.
- Кнопка аккаунта показывает email рядом с аватаром, только если блоку инструментов шапки хватает места: блок занимает остаток после навигации и объявлен контейнером (`container-type`), правило - `@container` в `account-menu.module.css`. Меню: email, роль, «Выйти». Роль и email берутся из `useCurrentUser()` (`@shared/auth`).
- Страница встраивается в каркас только содержимым: возвращает заголовок `PageTitle` и острова `Island` из `@shared/ui`, отступы между ними задаёт каркас. Короткая подпись раздела - `note` у `PageTitle`: она стоит рядом с заголовком, а если в шапке тесно или на телефоне - под ним. Кнопки и поля шапки выровнены по нижнему краю заголовка. Окна - `Modal` Mantine с `classNames={dialogClassNames}` и частями из `@shared/ui/dialog` (`DialogActions`, `DialogError`, `DialogInfo`, `DialogSubject`, `DialogText`). Таблица или список на телефоне выбираются `useMatches` по брейкпоинту `sm`, как навигация. Логотип Aéza - `@shared/ui/aeza-logo`, его геометрия из брендбука не меняется.
- Тема Mantine по брендбуку Aéza (`../docs/Аеза_Гайдбук_2026.pdf`) - `src/shared/ui/theme`: палитры в `palettes.ts`, настройки компонентов в `theme.ts`, токены `--nz-*` для светлой и тёмной схем в `tokens.ts` (оттенки берут из палитр), `ThemeRoot` - корень `MantineProvider` (шрифты, схема по умолчанию из настроек системы). Стили Mantine подключаются в CSS-слое `mantine`, поэтому CSS-модули перебивают их без `!important`.
- Палитры `gray` и `dark` перенастроены под бренд, а встроенные цвета Mantine (наведение `gray-light`, неактивное `disabled`, предупреждения `red-light` и `yellow-light`, подсказка в поле) строятся из них. Поэтому они переопределены в `tokens.ts`, а наведение пунктов списков и меню, крестик окна, невыбранные переключатели и флажки - классами в `theme.ts`. Новый компонент Mantine сначала проверяется в обеих схемах. Поле на холсте цвета кнопок (`--nz-field`), внутри острова и окна утоплено (`--nz-inset`). Заголовки окон `Modal` и листов `Drawer` задаёт тема, листы получают поверхность окна.
- Цели нажатия на телефоне (меньше `sm`) не ниже 44 px. Это правило темы для `Button`, `ActionIcon` (размеры `md`, `lg`), полей, `CloseButton`, `SegmentedControl` и пунктов `Menu`, высоты по месту не задаются. Иконка-кнопка в строке - `size='lg'`, а не число. Кнопка «Добавить …» в шапке раздела - `AddButton` из `@shared/ui/add-button`: на телефоне это квадратная «+».
- Цвета в CSS-модулях - только токены `--nz-*` (`var(--nz-island)`, `var(--nz-ink-2)`) и переменные палитр Mantine, свои hex-значения не заводим. Приглушённый текст - `<Text c='dimmed'>`, ссылки внутри приложения - `Anchor` с `renderRoot` на `Link` роутера. Суммы, даты и счётчики набираются с `font-variant-numeric: tabular-nums`.
- API - `src/shared/api`: клиент, типы, опции запросов TanStack Query и обработчики MSW генерируются в `generated/` (`pnpm api:generate`), импортируются из `@shared/api`. Ошибки в формате Aéza v2 разбирают `getApiErrorCode`, `getRetryAfterMinutes`, `getApiFieldErrors` (тексты полей из `payload` ответа `400` - под поля формы) и `getApiErrorMessage` (текст сервера или «Не удалось связаться с сервером…»); экраны сравнивают коды (`not_a_member`), а не статусы. Справочник отделов - `departmentsOptions()`, предел списков `LIST_LIMIT`, догрузка страниц - `nextOffset`. Свой код запросов и типы ответов руками не пишем.
- Суммы и даты - `src/shared/lib/money` (`formatMoney`: из минимальных единиц, «150 000,00 ₽») и `src/shared/lib/dates` (дата API - строка `YYYY-MM-DD`; `formatDate`, `daysBetween`, `addDays`, `addMonths`, `startOfMonth`, `endOfMonth`). Даты срока и оплаты не переводятся в `Date` с часовым поясом браузера: арифметика идёт через полночь UTC. «Сегодня» и окно напоминания берутся с сервера - `settingsOptions()` из `@shared/api` (`GET /settings`); маршрут, которому нужна дата, ждёт его в `loader`.
- Общие мелочи `shared/lib`: `capitalize` (`text`), `usePhone` (`media`: раскладка телефона, уже `sm`), `fieldError` (`form`: ошибка поля TanStack Form), список валют `CURRENCIES` (`money`); названия ролей `ROLE_LABELS` - в `@shared/auth`.
- Склонение после числа («5 дней», «2 платежа») - `plural`, `pluralWord` (только слово) и `formatDays` из `@shared/lib/plural`. Пустой список и ошибка загрузки внутри острова - `ListState` и `LoadError` из `@shared/ui/list-state`.
- Моменты времени из API (`createdAt`, `linkedAt`, `expiresAt`) - `formatMoment`, `formatMomentTime` и `formatTimeOfDay` из `@shared/lib/dates`: в отличие от календарных дат они показываются в часовом поясе браузера.
- `ThemeRoot` монтирует ещё `DatesProvider` (русский календарь, неделя с понедельника) и `Notifications` внизу по центру; на телефоне нижние уведомления подняты над нижней панелью разделов. Уведомления показывает `notifications.show` из `@mantine/notifications`; одно уведомление с постоянным `id` перед показом скрывается (`notifications.hide`): Mantine не показывает второе с тем же `id`.
- Раздел «Платежи» - `src/pages/payments`. Состояние экрана в адресе (`validatePaymentsSearch` у маршрута): `from`, `to` (вид периода выводится из них: границы месяцев - «Месяц», только `to` - «На дату», иначе «Период»; без дат - этот и следующий месяц), `dept` (`none` - без отдела), `status`, `currency`, `order`, `page`, `payment` (окно платежа по прямой ссылке `PaymentDialog`: последние 12 периодов с действиями страницы); значения по умолчанию в адрес не пишутся. Статус периода - `occurrenceStatus` из `@entities/payment-occurrence` (там же значок `StatusMark` и цвета `TONE_CLASS`) по `overdue` и `daysOverdue` с сервера и дням до срока. Запись - `useOccurrenceActions`: после неё перечитываются все запросы периодов и итогов (`invalidatePayments`). На телефоне (меньше `sm`) карточки с «Показать ещё» (`usePhoneOccurrences`) и листы снизу (`Drawer`) вместо меню и модальных окон.
- Виды «Платежей» - `view` в адресе: таблица по умолчанию, «Календарь» и «Бюджет» (у бюджета свой `year`, период таблицы не трогает). Страница (`payments-page.tsx`) держит адрес, шапку и общие окна, а каждый вид - свой экран со своими запросами: `TableScreen`, `CalendarScreen`, `BudgetScreen` (общие пропсы - `ScreenProps`). Календарь берёт созданные периоды за месяцы сетки и плановые из `GET /payments/forecast`; все страницы одного списка грузятся одним запросом, остальные после первой - параллельно (`model/views-queries.ts`); месяцы, недели и дата появления планового периода - `lib/calendar.ts`. Бюджет - один `summary` за год с `groupBy=month` и `includePlanned`, подписи месяцев - `lib/budget.ts`. `SummaryCards` складывают `plannedMinor` и `plannedCount` с неоплаченным; итоги запрашиваются с `includePlanned`, если у периода есть конец. В таблице и карточках плановые периоды встают по сроку на свою страницу: границы - последний срок этой и предыдущей страницы (`lib/planned.ts`, `usePreviousPageLast`), у них нет действий.
- Раздел «Регулярные платежи» - `src/pages/recurring-payments`. Фильтры в адресе (`validateRecurringSearch`): `status` (`stopped`, `all`; по умолчанию действующие), `dept`, `page`. Карточка платежа - дочерний маршрут `recurring-payments.$paymentId.tsx` (`RecurringPaymentCard`, панель `Drawer` поверх списка, на телефоне во весь экран); закрытие возвращает на список с теми же фильтрами. Окна создания, изменения, прекращения и возобновления общие для списка и карточки (`usePaymentDialogs`). Форма платежа - `PaymentFormDialog` из `@features/recurring-payment-form` (схема, значения и тела запросов - в его `model/payment-form.ts`), ею пользуются и «Регулярные платежи», и «Платежи» (кнопка «Добавить платёж» у администратора). Форма разбирает сумму `parseAmount` из `@shared/lib/money`, периодичность выбирает из готовых вариантов или «раз в N дней, недель, месяцев, лет» (`period`, `periodCount`), число оплат `occurrenceLimit` (пусто - бессрочно), в `PATCH` шлёт только изменённые поля, при создании держит один `Idempotency-Key`, пока тело не изменилось. Расписание по периодичности (`nextDueAfter`, `scheduleLabel`, `periodLabel`, `nextDuesHint`, `anchorNote`) подписи и метки платежа («прекращён», «завершён», «просрочено N дн.») - в `@entities/recurring-payment`. После записи `useRefreshRecurring` оттуда же перечитывает платежи, периоды, итоги, прогноз и отделы через `invalidateOperations` из `@shared/api`.
- Раздел «Уведомления» - `src/pages/notifications`: личный Telegram у всех, групповые чаты у администратора. Ссылку на бота и ожидание привязки ведёт `useLinkFlow`: пока ссылка действует, запрос перечитывается каждые 3 секунды, а ожидание заканчивается, когда данные изменились относительно снимка на момент запроса или ссылка устарела. QR-код ссылки рисуется из матрицы `uqr`, светлым в обеих схемах. Окно «Какие платежи присылать» общее для личного фильтра и групп. Группа подключается одним кодом двумя способами (`GroupLinkSteps`): ссылкой «Открыть Telegram» без темы или командой `command` в нужной теме; каждое подключение темы - отдельный элемент списка, подпись «Группа → Тема» даёт `chatLabel`.
- Раздел «Журнал» - `src/pages/audit-log`, только администратор (`/audit`). Запись словами (действие, объект, что изменилось) строит одна чистая функция `describeEntry` по коду действия и `details`; таблица и карточки рисуют одно описание. У входа это IP и браузер с системой (`userAgentLabel` в `lib/user-agent.ts`), полный User-Agent - в подсказке строки: `Tooltip` в таблице, `Popover` по нажатию в карточках телефона. Фильтры (группа действий, автор, период; по умолчанию последние 30 дней) - в адресе, даты переводятся в моменты начала и конца дня браузера. Записи подгружаются по 50 (`useInfiniteQuery`), группируются по дням в часовом поясе браузера.
- Сессия - `src/shared/auth`: токен, срок и email в хранилище zustand, которое middleware `persist` держит в `sessionStorage` (ключ `nezabudka-session`). `connectApiClient` подставляет токен в запросы, а при `401 not_auth` держит запрос до повторного входа (`requestReauth`) и повторяет его; запрос с `reauth: false` (выход, уже повторённый) не ждёт. `connectTabs` делит сессию между вкладками через `BroadcastChannel`, не задерживая первый рендер: ответа других вкладок ждут маршруты через `whenTabsReady`. Оба вызываются в `src/app/main.tsx`. Выход - `signOut()`, профиль - `currentUserOptions()` и `useCurrentUser()` (кэш 5 минут).
- Схем две, светлая и тёмная: пока человек не выбрал, действует схема системы (`auto` у Mantine). Переключатель - `useColorSchemeToggle` и кнопка `ColorSchemeToggle` для страницы входа из `@shared/ui/color-scheme-toggle`. Место под полосу прокрутки занято всегда (`scrollbar-gutter` в `global.css`), чтобы шапка не сдвигалась между длинной и короткой страницей; на время открытого окна его освобождает правило с `body[data-scroll-locked]`.
- Выбранная схема хранится в `localStorage` под ключом `COLOR_SCHEME_STORAGE_KEY` из `src/shared/ui/theme/color-scheme.ts`. Тот же ключ читает скрипт в `<head>` `index.html`: он ставит схему до загрузки приложения. Ключ меняется в обоих местах сразу, совпадение проверяет тест темы.
- В CSS-модулях классы в camelCase (`styles.pageTitle`), значения - через переменные темы (`var(--mantine-spacing-md)`). Миксины `@mixin dark`, `@mixin hover` и функция `rem()` - из `postcss-preset-mantine`.

## Экраны

По [../docs/Case.md](../docs/Case.md):

- вход аккаунтом Aéza (ADR-014): своя страница входа с шагом кода 2FA; без сессии любой раздел ведёт на вход, истёкшая сессия открывает окно повторного входа поверх страницы; "Выйти" завершает сессию на сервере и во всех вкладках;
- список периодов: название, сумма, валюта, срок, статус, дата оплаты, просрочка; отметка и отмена оплаты, исправление фактической даты;
- итоги по валютам, каждая валюта отдельно;
- уведомления (каждый пользователь): подключение личного Telegram по ссылке на бота, включение и выключение личных напоминаний, отвязка (ADR-010);
- только администратор: регулярные платежи (создание, изменение, прекращение), пользователи (создание, изменение, удаление) и отделы (создание, переименование, удаление; ADR-012).

## Контракт и backend для разработки

- Контракт API - `../backend/api/openapi.yaml` (OpenAPI 3.1). Его выгружает backend из кода, руками не правится.
- Локальный backend со входом без Aéza (из корня репозитория, нужен Docker): `docker compose -f infra/compose.dev.yaml up -d --build`, api - на http://localhost:8000, его и ждёт `pnpm dev`. Тестовые аккаунты (администратор, администратор с 2FA, пользователь) и общий пароль - в [../infra/README.md](../infra/README.md).
- Тестовый стенд: `API_PROXY_TARGET=https://nezabudka.space` в `.env.local`. Пароль dev-входа на стенде знает команда, в репозиторий он не попадает.
- Без Docker и сети - mock-сервер по контракту (из корня репозитория): `npx -y @stoplight/prism-cli@5 mock backend/api/openapi.yaml -p 4010`, dev-сервер - с `API_PROXY_TARGET=http://localhost:4010`. Mock отдаёт примеры из схем и проверяет запросы по контракту, но настоящего входа и ошибок в нём нет.
- Mock требует заголовок `Authorization: Bearer <что угодно>`, иначе отвечает 401: так же будет вести себя настоящий API.
- Поля со значением `null` в примерах mock не отдаёт (их убирает FastAPI при сборке контракта): считай отсутствующее поле равным `null`.
- `operationId` в контракте - имя функции backend (`list_payment_occurrences`, `create_recurring_payment`): по нему генератор строит функции клиента (`listPaymentOccurrences`), опции запросов (`listPaymentOccurrencesOptions`) и обработчики MSW для тестов (`handleListPaymentOccurrences`). Имя, которое начиналось бы с `use` и выглядело бы хуком, переименовывается в `parser.patch.operations` в `openapi-ts.config.ts`: так `use_challenge` генерируется как `exchangeChallenge`.

## Правила

- Интерфейс на русском языке. Тексты короткие и простые, без поясняющих оборотов через тире.
- Неразрывный пробел (nbsp) после однобуквенных предлогов и союзов (в, к, с, о, у, а, и, я), по месту после коротких («от», «до», «за») и между числом и единицей («7 мин.»): в JSX-тексте - `&nbsp;`, в строках - `'\u00a0'`. Сам символ в код не вставляем: его не видно, а ESLint (`no-irregular-whitespace`) ловит его в JSX и шаблонных строках.
- Типы запросов и ответов генерируются из контракта `../backend/api/openapi.yaml`, руками не правятся.
- Права решает сервер. Frontend скрывает недоступные действия по роли из `/api/v1/auth/me`, но защитой это не считается.
- Суммы приходят в минимальных единицах валюты: перевод в отображаемую сумму в одном месте, валюты не смешиваются.
- Даты срока и оплаты - без времени, не переводятся через часовой пояс браузера. Компоненты `@mantine/dates` отдают строки `YYYY-MM-DD`: их и передаём в API, без `Date`.

## Скиллы

- Фронтовые скиллы лежат в `frontend/.agents/skills/`; `frontend/.claude/skills` - симлинк на неё. Общие правила по скиллам - в корневом [AGENTS.md](../AGENTS.md).
- Свои скиллы называем с префиксом `frontend-`. Сторонние ставятся из `frontend/` командой `npx skills add <репозиторий> --skill <имя> -a codex`: так CLI пишет только в `.agents/skills` и не трогает симлинк. Источники записаны в `skills-lock.json`.
- Тесты - по скиллу [`frontend-testing`](.agents/skills/frontend-testing/SKILL.md): сначала реши, нужен ли тест, и не покрывай косметику, гарантии библиотек и несуществующие ветки.
- Структура кода - `feature-sliced-design`. Маршруты - `react-router`, `router-core`, `router-plugin`, `router-query`. Запросы - `tanstack-query-best-practices`. Свои компоненты на основе Mantine - `mantine-custom-components`.
- Вёрстка - `interface-design` и `no-ai-design-slop`.
- Перед работой над фронтом запускай агента из папки `frontend/`.

## MCP

- Playwright MCP подключён в `frontend/.mcp.json`: агент открывает приложение в headless-браузере, делает скриншоты и проходит сценарии. Нужен Google Chrome. Снимки и логи пишутся в `.playwright-mcp/`, папка в `.gitignore`. После `browser_navigate` дождись текста страницы (`browser_wait_for`): холодный dev-сервер отдаёт пустую страницу первые секунды.
- Документацию библиотек даёт Context7. Его каждый подключает себе сам, со своим ключом: `claude mcp add --scope user --transport http context7 https://mcp.context7.com/mcp --header "CONTEXT7_API_KEY: <ключ>"`. В `.mcp.json` он не лежит, потому что проектная запись перекрыла бы личный ключ.
