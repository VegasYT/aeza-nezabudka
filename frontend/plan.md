## 3. Платежи: список периодов и отметка оплаты

Главный экран, без него не проходит ни один шаг защиты.

- [x] Общие правила для всех экранов: сумма из минимальных единиц и валюта - в одном месте (`shared`), дата срока без часового пояса браузера, табличные тесты
- [x] Список периодов `GET /payment-occurrences`: название, сумма, валюта, срок, статус, дата оплаты, просрочка (`overdue`, `daysOverdue` с сервера), отдел
- [x] Статусы: не оплачено, оплачено, оплачено с просрочкой, просрочено на N дней
- [x] Отметка оплаты в одно действие (`PATCH`, `paid: true`, дата - сегодня)
- [x] Исправление фактической даты: выбор даты не позже сегодня, просрочка пересчитывается сразу
- [x] Отмена отметки (`paid: false`)
- [x] Пустой список, загрузка, ошибка; пагинация `limit` и `offset`
- [x] После записи и при возврате на вкладку список перечитывается
- [x] Телефон: карточки вместо таблицы

## 5. Регулярные платежи (администратор)

- [x] Список `GET /recurring-payments`: название, сумма, валюта, ближайший срок, отдел, действует или прекращён
- [x] Создание: название, сумма, валюта, дата ближайшей оплаты (не раньше сегодня), периодичность «ежемесячно», отдел
- [x] Изменение `PATCH`: пояснение, что правка касается только будущих неоплаченных периодов; прекращённый платёж не меняется (409)
- [x] Прекращение `DELETE` с подтверждением: история остаётся, напоминаний больше нет
- [x] Карточка платежа - боковая панель поверх списка со своим адресом `/recurring-payments/{id}`: данные, история периодов (`GET /payment-occurrences?recurringPaymentId=`), «Изменить» и «Прекратить»
- [x] В `PATCH` только изменённые поля: `nextDueDate` без изменений пересоздаёт периоды и шлёт напоминание повторно
- [x] Ошибки проверки 400 из `payload` - под полями формы
- [x] Периодичность: готовые варианты и «раз в N дней, недель, месяцев, лет» (`period`, `periodCount`); расписание в списке и карточке по периодичности
- [x] «Добавить платёж» у администратора и на экране «Платежи» (шапка, телефон, пустой экран)
- [x] Число оплат (`occurrenceLimit`): «Сколько раз оплатить» в форме, «оплачено N из M» и «завершён» в списке и карточке
- [x] Возобновление прекращённого платежа `POST /recurring-payments/{id}/resume`: по прежнему расписанию или с выбранной даты
- [x] Прямая ссылка на платёж `/payments?payment=<id>` для всех ролей (кнопка «Открыть в панели» в Telegram)

## 6. Уведомления: личный Telegram (каждый)

- [x] Состояние `GET /me/telegram`: привязан ли, имя в Telegram, включены ли личные напоминания, заблокирован ли бот
- [x] «Подключить Telegram» `POST /me/telegram/link`: ссылка на бота и QR-код, ожидание привязки с перечитыванием; бот не настроен (409) - объяснение

- [x] Бот заблокирован - как снова запустить; подключён ли общий чат, образцы напоминаний
