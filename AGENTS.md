# AGENTS.md

## Проект

Invoice Keeper - система напоминаний о регулярных платежах (кейс компании Aéza, хакатон РнД). Полное описание: [docs/Case.md](docs/Case.md).

Сценарий: бухгалтерия компании забывает оплачивать регулярные счета. Администратор (email аккаунта Aéza в `.env`) вносит регулярные платежи: аренда, подписки, серверы. Система за 3 дня до срока пишет в общий Telegram-чат, а каждому пользователю, который этого захотел, ещё и в личный чат с ботом. Пользователи видят общий список, отмечают оплату конкретного периода и следят за просрочками. Валюты RUB, USD, EUR, итоги по каждой отдельно, без конвертации.

Основные возможности:
- регулярные платежи с любым периодом: каждые N дней, недель, месяцев или лет (по умолчанию раз в месяц), бессрочно или заданное число раз; у каждого периода свой срок и своя отметка оплаты;
- отметка и отмена оплаты, исправление фактической даты, просрочка со следующего дня после срока;
- напоминания в Telegram минимум за 3 дня, без дублей: в общий чат и по желанию пользователя в личный (ADR-010);
- вход аккаунтами Aéza и белый список с ролями администратор, пользователь, интеграция; ограничения действуют и в API (ADR-014);
- REST API `/api/v1` с OpenAPI-спецификацией и Swagger;
- отделы как необязательная группировка платежей (ADR-012);
- встраивание: события на webhook и в Kafka заказчика, доступ к API для других систем по `X-API-KEY` аккаунта Aéza (ADR-011).

Система ставится on-premise у одной компании, multi-tenancy нет.

Архитектурные решения - [docs/ADR.md](docs/ADR.md), состав системы и этапы - [docs/plan.md](docs/plan.md). Стек backend - FastAPI с модулями в `backend/apps/` (ADR-013), стек frontend - React, Vite, TypeScript, Mantine ([frontend/AGENTS.md](frontend/AGENTS.md)).

## Структура (монорепо)

- `frontend/` - веб-панель. Свои правила: [frontend/AGENTS.md](frontend/AGENTS.md).
- `backend/` - API, фоновая задача напоминаний, Telegram-бот. Свои правила: [backend/AGENTS.md](backend/AGENTS.md).
- `infra/` - Docker Compose и выкладка (появится на этапе 1).
- `docs/` - описание кейса и проектная документация.
- `openspec/` - спецификации и изменения (spec-driven процесс через OpenSpec).
- `.agents/skills/` - общие скиллы для всего репозитория.

Работая над одной частью репо, запускай агента из её папки (например, из `frontend/`): так подхватываются её `AGENTS.md` и скиллы вместе с корневыми.

## Процесс

- Новое поведение и изменение принятого решения идут через OpenSpec change: `openspec-propose`, затем `openspec-apply-change`, после проверки `openspec-archive-change`.
- Код не противоречит [docs/ADR.md](docs/ADR.md). Если задача требует отступить от ADR, сначала меняется ADR.
- Контракт API - `backend/api/openapi.yaml`. Его правка затрагивает и backend, и frontend.
- Документация, комментарии в коде и интерфейс - на русском. Имена в коде, файлах и capability - на английском.
- Секреты не коммитятся: только `.env.example` без реальных значений.

## Скиллы

- Источник скиллов - папка `.agents/skills/`: в корне для общих скиллов, в `frontend/`, `backend/`, `infra/` для скиллов своей части. Скиллы добавляются и редактируются только там.
- Рядом с каждой `.agents/skills/` лежит симлинк `.claude/skills` -> `../.agents/skills`. Не заменяй его обычной папкой и не копируй скиллы в `.claude/` или другие каталоги агентов.
- Если инструменту нужен свой путь к скиллам, подключай его симлинком на `.agents/skills`, а не копией.
- Скилл кладётся в ту часть репо, к которой относится. В корне только то, что нужно всем (OpenSpec, git, общие правила).
- Имена скиллов частей репо начинаются с префикса части: `frontend-...`, `backend-...`, `infra-...`. Сторонние скиллы сохраняют своё имя.
- Каждый скилл - отдельная папка `<имя>/SKILL.md` с frontmatter (`name`, `description`).
- Если агент запущен из корня, а задача касается части репо, сначала прочитай `<часть>/AGENTS.md` и релевантные `<часть>/.agents/skills/*/SKILL.md`: из корня они могут не подгрузиться автоматически.

### Симлинк на Windows

Если клонировать репозиторий на Windows без включенных симлинков, `.claude/skills` будет обычным текстовым файлом, а не ссылкой, и Claude Code не увидит скиллы. Под Linux и macOS всё работает сразу, под WSL - если и git, и агент запускаются внутри WSL.

Что нужно на Windows:

1. Включить режим разработчика (Параметры - Для разработчиков) либо запускать git от администратора.
2. Клонировать с включенными симлинками:

   ```bash
   git clone -c core.symlinks=true <url>
   ```

Если репозиторий уже клонирован и симлинки оказались файлами, пересоздай каждый:

```bash
git config core.symlinks true
rm .claude/skills frontend/.claude/skills backend/.claude/skills
git checkout -- .claude/skills frontend/.claude/skills backend/.claude/skills
```

Проверка: `ls -la .claude/ frontend/.claude/ backend/.claude/` должен показать `skills -> ../.agents/skills`.

Не запускай `openspec init` и `openspec update` с `--tools claude`: они заменят симлинк обычной папкой. Используй `--tools codex`.
