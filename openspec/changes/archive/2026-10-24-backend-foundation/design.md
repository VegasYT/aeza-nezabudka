# Design

## Context

`backend/` пуст, кроме документов. Стек, структура и команды заданы в ADR-013 и `backend/AGENTS.md`. Разработка идёт на Windows, а образ и сервер - Linux; интеграционные тесты требуют Docker.

## Goals / Non-Goals

**Goals:**

- каркас, на который шаги 2-11 добавляют только модули `apps/` и миграции, не трогая общий код;
- быстрые тесты без Docker и интеграционные тесты на настоящем PostgreSQL одной командой `pytest`.

**Non-Goals:**

- HTTP-сервер у `worker` и метрики (шаг 10);
- compose всей системы (общий этап "Фундамент").

## Decisions

### Плоская раскладка и проект без сборки

Пакеты `app/`, `core/`, `apps/` лежат прямо в `backend/`, проект uv объявлен без сборки пакета (`[tool.uv] package = false`), запуск через `uv run` из `backend/`. Альтернатива - раскладка `src/` с устанавливаемым пакетом: она защищает от импорта "мимо установки", но нам не нужно публиковать пакет, а лишний уровень каталогов мешает командам из `AGENTS.md`. Решение выведено из ADR-013 и структуры в `backend/AGENTS.md`.

### Настройки: один объект, секреты как `SecretStr`

`core/config.py` - класс pydantic-settings, создаётся один раз при старте процесса. Секреты (`ADMIN_PASSWORD`, токены, секреты клиентов) объявлены `SecretStr`: при печати и в ошибках валидации их значения скрыты. Ошибка валидации перехватывается в точке входа, печатается список имён переменных, процесс завершается с кодом 1. На этом шаге обязательны только `DATABASE_URL` и `TZ`; остальные переменные добавят шаги, которым они нужны.

### "Сегодня" через `Clock`

`core/clock.py`: протокол `Clock` с методом `today()`, реализации системная (текущая дата в `TZ` через `zoneinfo`) и фиксированная (для `CLOCK_TODAY` и тестов). Экземпляр выбирается при старте по настройкам и отдаётся сервисам через зависимости FastAPI и конструктор задач `worker`. Запрет `CLOCK_TODAY` при `APP_ENV=production` - валидатор настроек, поэтому он срабатывает и в `api`, и в `worker`, и в миграциях. На Windows нет системной базы часовых поясов, поэтому в зависимости добавлен пакет `tzdata`.

### Ошибки: исключения предметной области и обработчики

`core/errors.py`: базовое исключение `AppError` с `status`, `code`, `message`, `fields`; обработчики FastAPI переводят в общий формат его, `RequestValidationError` (422, `fields` из ошибок Pydantic), `HTTPException` от Starlette (404, 405) и любое другое исключение (500, без деталей, трассировка в журнал). Модули `apps/` бросают наследников `AppError` и не формируют ответы сами.

### Журнал и идентификатор запроса

structlog с выводом JSON, стандартный `logging` (uvicorn, SQLAlchemy, Alembic) направлен в тот же обработчик, чтобы весь вывод процесса был JSON. `request_id` хранится в `contextvars` и добавляется в каждую запись. Middleware на чистом ASGI (не `BaseHTTPMiddleware`, который ломает потоковые ответы и contextvars): берёт `X-Request-ID`, если он из 1-128 символов `[A-Za-z0-9._-]`, иначе создаёт UUID4, кладёт в ответ. Журнал запроса пишет метод, шаблон пути, код и длительность; заголовки и тело не пишутся вовсе, поэтому `Authorization` в журнал не попадает. Дополнительно процессор structlog заменяет значения ключей с именами вида `password`, `token`, `secret`, `authorization` на `***`.

### База: async engine и сессия на сценарий

`core/db.py`: `create_async_engine` с asyncpg, `async_sessionmaker(expire_on_commit=False)`, базовый класс моделей с соглашением имён ограничений (чтобы Alembic давал стабильные имена). Зависимость FastAPI отдаёт сессию; транзакцию открывает сервис (`backend/AGENTS.md`). Пул: размер из настройки `DATABASE_POOL_SIZE` (по умолчанию 10).

### Готовность: живая база и последняя миграция

`/readyz` выполняет `select version_num from alembic_version` с таймаутом 2 секунды и сравнивает с головой `ScriptDirectory` Alembic, прочитанной при старте. Недоступная база - 503 `database_unavailable`, другая версия или нет таблицы - 503 `migrations_pending`. Альтернатива - проверять только соединение - пропустила бы запуск `api` до `migrate`, а тогда первые запросы падали бы на отсутствующих таблицах.

### Alembic в асинхронном режиме

Шаблон `alembic init -t async`, URL берётся из настроек, а не из `alembic.ini`, метаданные - из базового класса моделей; модели всех модулей импортируются в `migrations/env.py` через один модуль-реестр, чтобы автогенерация видела все таблицы. Первая миграция пустая: она фиксирует начало истории и даёт `/readyz` что сравнивать.

### Worker: TaskGroup и событие остановки

`app/worker.py`: список фоновых задач (на этом шаге пустой), каждая - цикл "сделать единицу работы, подождать интервал или событие остановки". Сигнал ставит `asyncio.Event`; задачи проверяют его между единицами работы, поэтому начатая единица доводится до конца. Ожидание завершения ограничено `SHUTDOWN_TIMEOUT`, после него задачи отменяются. На Windows `loop.add_signal_handler` не работает, поэтому там обработчик ставится через `signal.signal` с передачей в цикл через `call_soon_threadsafe`. Чтобы проверять это без процесса, цикл задач принимает событие остановки параметром; тест сам выставляет событие.

### Тесты: один контейнер на сессию, откат на тест

Фикстура сессии pytest поднимает PostgreSQL 17 через testcontainers и применяет миграции командой Alembic. Каждый тест получает соединение с открытой транзакцией, а сессия работает в режиме `join_transaction_mode="create_savepoint"`: коммиты сервиса становятся точками сохранения, в конце теста всё откатывается. Тесты, которым нужен Docker, помечены `integration` и идут в общем `pytest`; `pytest -m "not integration"` их пропускает. API тестируется через `httpx.AsyncClient` с `ASGITransport`, без поднятия сервера. Тест "база недоступна" использует отдельный engine на заведомо закрытый порт, а не останавливает общий контейнер.

### Образ

`python:3.12-slim`, бинарник uv копируется из официального образа `ghcr.io/astral-sh/uv`, зависимости ставятся `uv sync --frozen --no-dev` отдельным слоем до копирования кода, процесс работает от непривилегированного пользователя. Команда по умолчанию - `api`; `worker` и `migrate` задаются командой контейнера. Версии образов закреплены тегами.

## Risks / Trade-offs

- [Docker Desktop на Windows не запущен] -> интеграционные тесты падают при старте контейнера с понятной ошибкой; быстрые тесты идут через `pytest -m "not integration"`.
- [Сигналы на Windows] -> локально остановка по Ctrl+C проверяется вручную, а логика остановки покрыта тестом через событие; в контейнере Linux работает обычный SIGTERM.
- [Версии зависимостей уйдут вперёд] -> `uv.lock` коммитится, образ ставит строго по нему.
