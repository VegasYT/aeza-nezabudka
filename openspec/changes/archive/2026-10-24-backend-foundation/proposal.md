# Proposal

## Why

Backend ещё не существует: в `backend/` только документы. Шаги 2-11 из `backend/plan.md` опираются на общий каркас: настройки, базу, миграции, формат ошибок, логи, проверку готовности и процесс `worker`. Его нужно сделать первым и один раз, иначе каждый модуль заведёт это по-своему (ADR-013).

## What Changes

- Проект backend на Python 3.12 и uv с инструментами из ADR-013: ruff, mypy, pytest, import-linter.
- Общие части `backend/core/`: настройки из окружения с проверкой при старте, подключение к PostgreSQL, "сегодня" в часовом поясе `TZ` с подменой для демо, единый формат ошибок, JSON-логи с идентификатором запроса.
- Процесс `api`: FastAPI с префиксом `/api/v1`, Swagger на `/api/v1/docs`, `/healthz` и `/readyz`.
- Процесс `worker`: запуск фоновых задач и корректная остановка по сигналу; самих задач пока нет.
- Миграции Alembic в асинхронном режиме и первая пустая миграция.
- `Dockerfile` для `api`, `worker` и `migrate` из одного образа, `.env.example`.
- Обвязка тестов: PostgreSQL в контейнере, миграции на старте, откат изменений после каждого теста, фиксированная дата.

Вне изменения:

- эндпоинты предметной области и `api/openapi.yaml` (шаг 2);
- `infra/compose.yaml`, Keycloak и проверка токенов (этап "Фундамент" общего плана и шаг 4);
- `/healthz` и `/metrics` у `worker`, метрики `api` (шаг 10);
- таблицы предметной области (шаги 5-9).

## Capabilities

### New Capabilities

- `backend-platform`: общее поведение процессов backend - проверки живости и готовности, документация API, формат ошибок, проверка конфигурации при старте, идентификатор запроса и журнал, "сегодня" в часовом поясе системы, корректная остановка `worker`, применение миграций.

### Modified Capabilities

Нет: в `openspec/specs/` пока нет ни одной спецификации.

## Impact

- `backend/`: новый проект, пакеты `app/`, `core/`, `apps/`, `tests/`, `migrations/`, `pyproject.toml`, `Dockerfile`, `.env.example`.
- `backend/AGENTS.md`: команды из списка-цели становятся проверенными; `backend/plan.md`: статус шага 1.
- Frontend не затронут: контракт `backend/api/openapi.yaml` появится на шаге 2.
- Для интеграционных тестов нужен запущенный Docker.
