# Proposal

## Why

Главные критерии кейса - регулярные платежи с отдельными периодами, отметка и отмена оплаты, исправление даты, просрочка и итоги по валютам - пока работают только как функции домена, а эндпоинты отвечают 501. Шаг 5 `backend/plan.md` хранит платежи и периоды в базе и делает эндпоинты платежей рабочими; от них зависят напоминания (шаг 6), веб-панель и сценарий защиты.

## What Changes

- Таблицы `recurring_payments` и `payment_occurrences` с ограничениями базы и миграция.
- Регулярные платежи: создание с периодами до ближайшего будущего, список с фильтрами, платёж по идентификатору, изменение (название, сумма, валюта, дата ближайшей оплаты), прекращение с сохранением истории. Каждая запись - в журнал действий в той же транзакции.
- Периоды: список с фильтрами по статусу, валюте, платежу, отделу и сроку, сортировкой и страницами; период по идентификатору; отметка оплаты, исправление фактической даты и отмена с автором отметки.
- Итоги по валютам за диапазон сроков.
- Досоздание периодов для всех действующих платежей - функция сервиса, которую на шаге 6 вызовет `worker`.
- Ошибки: 422 для даты ближайшей оплаты раньше сегодня и даты оплаты позже сегодня, 404 для неизвестного платежа и периода, 409 для изменения и прекращения прекращённого платежа.

Вне изменения:

- отделы (шаг 8): поле `department_id` хранится, но отделов ещё нет, поэтому любой переданный отдел - 422 "Отдел не найден", а `department` в ответах всегда `null`;
- напоминания при создании платежа (шаг 6);
- интеграционные события и учёт `Idempotency-Key` (шаг 9): заголовок принимается, но пока не используется;
- запуск досоздания по расписанию (шаг 6).

## Capabilities

### New Capabilities

- `recurring-payments`: операции с регулярными платежами через API.
- `payment-occurrences`: просмотр периодов и отметка оплаты через API.

### Modified Capabilities

- `payment-totals`: добавляется требование к итогам через API с диапазоном сроков.
- `payment-schedule`: добавляется требование о досоздании периодов всех действующих платежей.

## Impact

- `backend/apps/payments`: `models.py`, `repository.py`, `service.py`, роутер; миграция; тесты на PostgreSQL в контейнере.
- `backend/app/main.py`: фабрика сессий передаётся приложению снаружи (для тестов с откатом).
- Контракт `backend/api/openapi.yaml`: поля и коды ответов прежние, меняются только описания; **затрагивает frontend** поведением: вместо 501 приходят рабочие ответы.
- `backend/plan.md`: статус шага 5.
