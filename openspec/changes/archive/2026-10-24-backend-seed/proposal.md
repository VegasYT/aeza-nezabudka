# Proposal

## Why

Сценарий защиты кейса требует показать просроченный платёж, оплату вовремя и с опозданием, напоминание за 3 дня и вход пользователем. API не принимает дату ближайшей оплаты в прошлом, поэтому такую историю руками не создать. Кейс прямо требует передать тестовые данные: аренда в рублях, сервер в долларах, подписка в евро. Основа шага 11 `backend/plan.md` делается сейчас, пока есть время её проверить.

## What Changes

- Команда `uv run python -m app.seed`: создаёт демонстрационные платежи с историей и пользователя для демо.
- Даты считаются от сегодняшнего дня запуска, а не зашиты в файл: демо не устаревает.
- Повторный запуск ничего не дублирует.
- Переменные `DEMO_USER_LOGIN` и `DEMO_USER_PASSWORD` для пользователя демо; `.env.example`, `backend/AGENTS.md`.

Вне изменения:

- отделы в тестовых данных и smoke-скрипт сценария защиты - дополнение шага 11 после шагов 8-10;
- запуск сида в compose - этап "Фундамент".

## Capabilities

### New Capabilities

- `demo-data`: состав и свойства демонстрационных данных.

### Modified Capabilities

Нет.

## Impact

- `backend/app/seed.py`, тесты, `core/config.py` (настройки сида), `.env.example`, `backend/AGENTS.md`, `backend/plan.md`.
- Контракт API не меняется.
