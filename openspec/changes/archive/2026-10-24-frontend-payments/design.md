# Design

## Context

- Раздел `/payments` - заглушка `src/pages/payments`. Маршрут `_authenticated/payments.tsx` только связывает адрес со страницей.
- Клиент API генерируется Hey API: опции запросов `listPaymentOccurrencesOptions`, `getPaymentsSummaryOptions`, `getSettingsOptions`, `listDepartmentsOptions`, мутация `updatePaymentOccurrenceMutation`. В dev клиент устарел относительно контракта (нет `/settings`, `departmentId=none`, счётчиков).
- Провайдеров `Notifications` и `DatesProvider` Mantine в приложении пока нет; `dayjs` и `@mantine/dates` уже в зависимостях.
- Макеты: холст, страница «Платежи» (`PayScreen`, `PayToolbar`, `PayPhoneScreen`). Контракт и семантика полей сверены с кодом бэкенда: `overdue` истинно и у «оплачено с опозданием»; `status=overdue` - только неоплаченные; итоги по валюте `totalMinor`, `paidMinor`, `unpaidMinor`, `overdueMinor` (входит в `unpaidMinor`).

## Goals / Non-Goals

**Goals:**
- Общий модуль сумм и календарных дат, на который потом сядут «Регулярные платежи», календарь и бюджет.
- Состояние экрана целиком в адресе: ссылку можно переслать, «назад» в браузере работает.

**Non-Goals:**
- Оптимистичные обновления: просрочку и итоги считает сервер, после записи перечитываем.
- Свой компонент календаря: берём `@mantine/dates`.

## Decisions

1. **Даты - строки `YYYY-MM-DD`, без `Date` с часовым поясом.** Срок и дата оплаты приходят строками; разница в днях считается по календарным датам (через UTC-полночь обеих дат), вывод `DD.MM.YYYY` - разбором строки. `@mantine/dates` работает со строковыми датами, поэтому в выборе даты тоже нет перевода в часовой пояс браузера. Альтернатива - `dayjs` с плагином UTC - тянет лишнее ради трёх функций; `dayjs` нужен только как локаль для календаря Mantine. Модуль - `src/shared/lib/dates`, суммы - `src/shared/lib/money` (`Intl.NumberFormat('ru-RU')` по минимальным единицам, знак валюты после суммы через неразрывный пробел, как в макетах). Табличные тесты на оба.
2. **«Сегодня» и окно напоминания - из `GET /settings`.** Опции запроса в `src/shared/api` (`settingsOptions()`, `staleTime` 5 минут, перечитывание при возврате на вкладку по умолчанию TanStack Query). `loader` маршрута `/payments` ждёт настройки (`ensureQueryData`): период по умолчанию зависит от сегодняшней даты сервера, и без этого первый кадр строился бы по часам браузера. Решение выведено из требования спецификации, не задано пользователем.
3. **Адрес страницы.** `validateSearch` маршрута простой функцией без zod (как у `/login`: zod не попадает в основной бандл). Поля: `from`, `to` (даты), `dept` (`none` или id), `status`, `currency`, `order`, `page`. Вид периода выводится из `from`/`to`: обе даты на границах месяцев - «Месяц», только `to` - «На дату», иначе - «Период»; пустые `from` и `to` - период по умолчанию (этот и следующий месяц от сегодня сервера). Значения по умолчанию в адрес не пишутся. Смена любого фильтра сбрасывает `page`.
4. **Запросы экрана.** Список (`limit` 50 на компьютере, `offset` по странице), итоги за период и отдел, а для строки о прошлой просрочке - список `status=overdue&to=<день до начала>&limit=1` (число) и итоги с тем же `to` (суммы `overdueMinor`). Отделы - `listDepartmentsOptions` для фильтра. При смене фильтров прежние данные остаются на экране до прихода новых (`placeholderData: keepPreviousData`), чтобы таблица не мигала. Телефон - `listPaymentOccurrencesInfiniteOptions` с «Показать ещё».
5. **Запись.** Одна мутация `updatePaymentOccurrence` для отметки, другой даты, исправления, отмены и «Вернуть». После успеха инвалидируются все запросы периодов и итогов (`listPaymentOccurrences*`, `getPaymentsSummary`). Строка, чья запись идёт, показывает «Сохраняем…» и не принимает нажатий (по переменным мутации). Ошибка 400 по `paidOn` идёт под поле в окне даты, остальные - уведомлением.
6. **Статус периода - чистая функция** `(период, сегодня, окно) → {вид, подпись, дни}` с табличными тестами. Живёт в слайсе страницы; в шаге 5 история в карточке платежа переиспользует её, тогда функция уйдёт в `entities`.
7. **Уведомления и календарь Mantine.** В `app` монтируются `Notifications` (`@mantine/notifications`, позиция внизу, на телефоне над нижней панелью) и `DatesProvider` (локаль `ru`, неделя с понедельника). Отмена оплаты показывает уведомление с кнопкой «Вернуть». В тестах Mantine с `env="test"` рисует их без портала.
8. **Слайсы FSD.** Экран - `pages/payments` (ui, model: статус, адрес, запросы). Шапка периода (`PeriodPicker`) пока в странице: календарь и бюджет из шага 10 живут на этой же странице. Значки, которых нет в `shared/ui/icons` (календарь, стрелки периода, галочка), добавляются туда; общие с «Пользователями» (плюс, карандаш, точки) берём из ветки соседней сессии после слияния.
9. **Форма входа.** Код `integration_account` (403 на `use-challenge` и `tfa/totp`) показывает то же объяснение, что и раньше; проверку роли после входа убираем, сервер сессию не выдаёт. Защитная проверка роли в `_authenticated` остаётся для сессий, выданных до правки бэкенда.

## Risks / Trade-offs

- [Около полуночи настройки устарели на 5 минут] → период по умолчанию и подписи «через N дней» отстают не дольше `staleTime`; сервер всё равно проверит дату оплаты и вернёт 400 под поле.
- [Четыре запроса на один вид экрана] → они параллельны и лёгкие; строка о прошлой просрочке не блокирует список.
- [Минимальная ширина таблицы ~1060 px] → на 1024 px таблица прокручивается вбок в своём контейнере, страница - нет.
