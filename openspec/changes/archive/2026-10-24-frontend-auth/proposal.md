# Proposal

## Why

Backend уже пускает только по сессии из входа через аккаунты Aéza (ADR-014, контракт в стиле Aéza v2, ADR-015), а веб-панель в API не ходит вовсе: без входа ни один экран не получит данных. Вход и роль нужны каждому следующему экрану, поэтому делаются первыми. Макеты согласованы на холсте https://claude.ai/artifact/HFAgCR6xiBb1mCw8q3s6mh, страница «Вход и доступ».

## What Changes

- Страница входа в два шага, как у Aéza: email и пароль аккаунта Aéza, затем код 2FA, если Aéza его требует. Понятные сообщения для неверного пароля, аккаунта не из белого списка, превышения попыток (через сколько минут повторить), недоступности Aéza, неверного кода и устаревшего входа.
- Аккаунт с ролью `integration` в панель не входит: панель сразу завершает его сессию и объясняет, что это аккаунт для интеграций.
- Сессия: токен хранится только в памяти вкладки (`sessionStorage`), открытые вкладки панели делятся им друг с другом, выход в одной вкладке завершает сессию во всех.
- Когда сессия закончилась посреди работы, поверх страницы открывается окно повторного входа тем же аккаунтом. Прерванные запросы ждут и выполняются после входа, введённое на странице не теряется. «Войти другим аккаунтом» - полный выход.
- Без сессии любой раздел ведёт на страницу входа, после входа - обратно в тот раздел.
- Роль в каркасе: разделы администратора (Регулярные платежи, Отделы, Пользователи) скрыты для роли «Пользователь»; открытый по прямому адресу раздел администратора показывает «Нет доступа» со ссылкой на Платежи.
- В шапке кнопка аккаунта: аватар и email (email прячется, когда в шапке тесно), меню с email, ролью и «Выйти».
- Фон страницы входа по брендбуку: в светлой схеме голубая панель с «é», в тёмной - чёрная панель с фирменным паттерном.
- Слой API во frontend: клиент и типы генерируются из `backend/api/openapi.yaml` (Hey API: axios, TanStack Query, MSW для тестов), ошибки в формате Aéza v2 разбираются в одном месте.
- Правило типографики: неразрывный пробел после коротких предлогов и союзов в текстах интерфейса.
- Убирается неиспользуемый `keycloak-js`, в `frontend/AGENTS.md` описание входа через Keycloak заменяется входом через Aéza.

Вне изменения:
- экран «Пользователи» (белый список) и остальные экраны с данными - следующие change;
- продление сессии: политика ADR-014 (12 часов без продления) остаётся;
- backend, контракт `backend/api/openapi.yaml` и документы в `docs/`;
- вход по `X-API-KEY`: он для других систем, не для панели;
- капча на входе Aéza: сейчас Aéza её не требует (`docs/plan.md`, раздел 5).

## Capabilities

### New Capabilities

- `web-auth`: вход в веб-панель аккаунтом Aéza, сессия во вкладках, повторный вход при истёкшей сессии, выход.

### Modified Capabilities

- `web-shell`: разделы навигации по роли вместо «все разделы видны до авторизации», кнопка аккаунта в шапке, страница «Нет доступа» для раздела администратора.
- `web-color-scheme`: переключатель схемы есть и на странице входа.

## Impact

- Часть репо: только `frontend/`.
- Код: слой API и сессия в `src/shared`, страница входа и окно повторного входа, защита маршрутов в `src/app/routes`, каркас `src/app/layout`, тесты маршрутов и каркаса.
- Зависимости: добавляются `@hey-api/openapi-ts` и `msw` (разработка и тесты), удаляется `keycloak-js`. Прокси `/api` в dev-сервере Vite на локальный backend.
- Контракт API не меняется: frontend только читает `backend/api/openapi.yaml`.
- Документация: `frontend/AGENTS.md` (вход, генерация клиента, типографика).
