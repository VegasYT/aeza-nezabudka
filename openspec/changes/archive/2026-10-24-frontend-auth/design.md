# Design

## Context

- Причины и объём - proposal.md, требования - specs `web-auth`, `web-shell`, `web-color-scheme`. Макеты: https://claude.ai/artifact/HFAgCR6xiBb1mCw8q3s6mh, страница «Вход и доступ».
- Контракт входа и ошибок уже в `backend/api/openapi.yaml` (ADR-014, ADR-015): `POST /auth/login` → `{challenge, requirements}`, затем `POST /auth/use-challenge` или `POST /auth/tfa/totp` → `{session, expiresAt}`, `GET /auth/me` → `{id, email, role}`, `POST /auth/logout`. Ошибка - `{statusCode, message, error, payload, requestId}`, `429` с заголовком `Retry-After` в секундах. Сессия 12 часов без продления.
- Во frontend нет ни клиента API, ни генерации типов, ни подмены API в тестах. `keycloak-js` в зависимостях, но не используется. Каркас `AppLayout` подключён компонентом корневого маршрута, все разделы видны всем.
- Backend локально - `uv run python -m app.main` на `:8000`; без backend есть Prism по контракту (`frontend/AGENTS.md`, раздел «Контракт и mock-сервер»).

## Goals / Non-Goals

**Goals:**
- Слой API, на котором следующие экраны получают данные без своего кода запросов и разбора ошибок.
- Сессия, которую видят и роутер, и клиент API, и все вкладки.

**Non-Goals:**
- Экран «Пользователи» и другие экраны с данными.
- Подмена API в браузере при разработке: для этого есть Prism.

## Decisions

### Клиент API: Hey API, сгенерированный код в репозитории

`@hey-api/openapi-ts` 0.99.0 (точная версия: до 1.0 мелкие версии меняют конфиг) читает `../backend/api/openapi.yaml` и пишет в `src/shared/api/generated/`: типы, функции операций по `operationId`, `xxxOptions()`/`xxxMutation()` для TanStack Query (плагин `@tanstack/react-query`), обработчики `handleXxx` для MSW 2 (плагин `msw`, поэтому сам `msw` 2.15.0, не 3.x). Клиент - `@hey-api/client-axios`.

- Генерация - команда `pnpm api:generate`, результат коммитится, как `routeTree.gen.ts`: сборка не зависит от папки backend, а изменение контракта видно в diff frontend. Папка исключается из ESLint, Prettier, Stylelint и Steiger.
- `use_challenge` переименован в `exchange_challenge` через `parser.patch.operations` конфига: иначе функция `useChallenge` выглядит как хук для ESLint и React Compiler.
- Профиль `GET /auth/me` кэшируется на 5 минут (`currentUserOptions`): его читают защита маршрута, форма входа и каркас, а роль меняется редко.
- Токен подставляет `auth: () => token` клиента: Hey API добавляет его только операциям с `security`, поэтому шаги входа уходят без заголовка.
- Выбор Hey API против Orval сделан пользователем (explore): токен по `security` без ручных исключений, `queryOptions` в стиле TanStack Query v5 для `loader` и `useQuery`, типизированные ошибки.

### Ошибки Aéza v2 разбираются в `shared/api`

Хелперы над сгенерированным `ErrorResponse`: код ошибки (`error`), текст для человека (`message`), минуты ожидания из `Retry-After` (секунды, вверх до целой минуты). Экраны сравнивают коды, а не статусы. Как клиент Hey API отдаёт ответ при ошибке (тело или объект axios с заголовками), сверить при реализации: заголовок `Retry-After` нужен из ответа, а не из тела.

### Сессия в `shared/auth`

По FSD токен - инфраструктура, поэтому живёт в `shared/auth`, а форма входа - пользовательское действие (`features/sign-in`). Хранилище - zustand (стек frontend): токен, `expiresAt`, email для окна повторного входа, состояние окна. Токен пишет в `sessionStorage` middleware `persist` (битое значение - нет сессии), роль не хранится: её даёт `GET /auth/me` через TanStack Query.

**Вкладки делятся токеном через `BroadcastChannel`** (решение пользователя). Вкладка без токена при старте спрашивает канал, открытые вкладки отвечают токеном. Первый рендер ответа не ждёт: его ждут до 150 мс только маршруты (`_authenticated` и `login`), когда сессии ещё нет. Одинаковую сессию из повторных ответов вкладка не ставит заново. Выход и новый токен после повторного входа тоже рассылаются в канал. На диск токен не попадает, после закрытия всех вкладок сессии нет. Канал доступен только скриптам того же origin, то есть тем же, кто и так читает `sessionStorage`.

### Повторный вход: очередь в интерцепторе axios

```
запрос -> 401 not_auth (запрос шёл с Bearer)
  -> интерцептор ждёт общий promise повторного входа (один на все упавшие запросы)
  -> окно повторного входа поверх страницы
       вход тем же email -> новый токен -> запросы повторяются с ним
       «Войти другим аккаунтом» -> promise отклоняется -> полный выход
```

- Повтор безопасен: `401` значит, что backend запрос не выполнял. Повторённый запрос и выход идут с `reauth: false` (поле конфигурации axios, Hey API передаёт его в запрос): их `401` окно не открывает.
- `beforeLoad` защищённых маршрутов при прошедшем `expiresAt` ждёт тот же promise, поэтому переход завершается после входа.
- Окно смонтировано во внутренней обёртке роутера (`InnerWrap` в `appRouterOptions`) через `ReauthHost`, который лениво грузит его только при открытии: форма с zod и TanStack Form не попадает в основной бандл. Не в корневом маршруте, потому что при первой загрузке с истёкшим сроком корневой маршрут не отрисуется, пока `beforeLoad` ждёт входа, а `InnerWrap` виден всегда и уже внутри контекста роутера. Там же наблюдатель сессии: сессия пропала (выход, другая вкладка, «Войти другим аккаунтом») - кэш запросов очищается, а `router.invalidate()` перезапускает защиту маршрута, и она открывает вход с `redirect` на текущую страницу.
- Email в окне берётся из хранилища сессии, поле не редактируется (решение пользователя), поэтому ветки «вошёл другой человек» нет.
- Альтернативы отклонены пользователем: продление сессии (`POST /auth/refresh`) меняет политику ADR-014; переход на `/login` теряет введённое на странице.

### Маршруты: `_authenticated` и `_admin`

По скиллу `router-core/auth-and-guards`:
- `routes/login.tsx` - вне каркаса; `validateSearch` (zod) берёт `redirect`; при действующей сессии `beforeLoad` ведёт на `/payments`.
- `routes/_authenticated.tsx` - `beforeLoad` проверяет сессию (нет - `redirect` на `/login?redirect=…`), при прошедшем сроке ждёт повторного входа, затем `ensureQueryData` для `me`; роль `integration` - выход и страница входа с объяснением. Компонент - `AppLayout`.
- `routes/_authenticated/_admin.tsx` - `beforeLoad` проверяет роль по кэшу `me` до загрузчиков разделов и бросает свою ошибку, `errorComponent` рисует страницу «Нет доступа». Адрес не меняется, поэтому страница внутри каркаса; `redirect` на отдельный адрес отвергнут.
- Разделы переезжают в `routes/_authenticated/` и `routes/_authenticated/_admin/`; адреса не меняются, `FileRoutesByTo` в `sections.ts` остаётся тем же.
- Неизвестный адрес ловит маршрут `_authenticated/$` (splat): «Страница не найдена» рисуется в каркасе и тоже требует входа. `notFoundComponent` не помогает: для несовпавшего адреса совпадает только корень, а безпутевой `_authenticated` в цепочку не попадает.

### Вход аккаунтом интеграции

После `use-challenge` или `tfa/totp` форма запрашивает `me`. Роль `integration` - `POST /auth/logout`, очистка сессии и сообщение на форме. Так выданная сессия не остаётся действовать.

### Кнопка аккаунта: email по container query

Блок инструментов шапки занимает оставшееся после навигации место (`flex: 1`, `min-width: 0`) и объявлен контейнером (`container-type: inline-size`). Email рядом с аватаром виден, только когда контейнер шире порога (`@container`). Пороги в px не зависят от вида навигации: место считает браузер. Доступное имя кнопки содержит email всегда. Меню - `Menu` Mantine с email, ролью и «Выйти».

### Страница входа

`pages/login`: форма из `features/sign-in` на холсте, слева панель бренда. Светлая схема - голубая панель с полупрозрачной «é» (глиф знака из `shared/ui/aeza-logo`), тёмная - чёрная панель с фирменным паттерном (три линии и акцентная со скруглённым поворотом). Панель и её вариант выбираются CSS по схеме (`@mixin light`/`@mixin dark`), без JS. На телефоне панель сжимается в полосу с логотипом, заголовок скрыт. Переключатель схемы в правом верхнем углу формы.

### Типографика

Неразрывный пробел после однобуквенных предлогов и союзов (в, к, с, о, у, а, и, я) и по месту после коротких («от», «до», «за»). В JSX-тексте - `&nbsp;` (ESLint `no-irregular-whitespace` ловит неразрывный пробел в JSX-тексте), в строках - `'\u00a0'`. Правило записывается в `frontend/AGENTS.md`.

### Разработка и тесты

- Dev-сервер Vite проксирует `/api` на `API_PROXY_TARGET`, по умолчанию `http://localhost:8000`; для Prism - `http://localhost:4010`.
- Тесты: MSW `setupServer` с обработчиками `handleXxx` из сгенерированного кода, общий хелпер в `shared/lib/test-utils` задаёт сессию и роль для `renderApp`. Хелпер вносится в таблицу скилла `frontend-testing`. Существующие тесты маршрутов и каркаса получают сессию администратора.

## Risks / Trade-offs

- [Защищённый маршрут в новой вкладке ждёт ответа канала до 150 мс] → ожидание только при отсутствии токена, рендер приложения не задерживается.
- [jsdom может не дать `BroadcastChannel`] → тесты синхронизации вкладок подменяют канал своей реализацией.
- [Hey API до 1.0] → точная версия, обновление вручную с перегенерацией и прогоном тестов.
- [В `openapi.yaml` остались ответы `422 HTTPValidationError`, которых по ADR-015 нет] → в типах это лишний вариант ошибки, разбор опирается на `ErrorResponse`. Сообщить backend-разработчику.
- [Окно повторного входа без крестика] → выход из него всегда есть: «Войти другим аккаунтом».
