# Proposal

## Why

Backend добавил два свойства регулярного платежа, которых панель пока не умеет:

- ограниченное число оплат: `occurrenceLimit`, `paidOccurrences`, `completed` (change `backend-occurrence-limit`, коммит `1dc3c56`). Например, «еженедельно в течение месяца» - это неделя, 1 и `occurrenceLimit: 4`;
- возобновление прекращённого платежа: `POST /recurring-payments/{id}/resume` (change `backend-payment-resume`, коммит `8a4a10f`).

Ещё одно замечание тестировщиков: в списке периодичности «Еженедельно» и «Раз в две недели» стоят после «Ежегодно», хотя список удобнее читать от частого к редкому.

## What Changes

- Число оплат:
  - в форме поле «Сколько раз оплатить»: пусто - бессрочно, иначе 1-1000;
  - при создании под полем дата последней оплаты;
  - при изменении поле уходит в `PATCH`, только если его поменяли. Пустое поле снимает ограничение. Меньше уже оплаченных и просроченных периодов нельзя;
  - в списке и карточке «оплачено 2 из 4»;
  - завершённый платёж помечен «завершён», вместо ближайшего срока подпись «все оплаты сделаны»;
  - строка под историей говорит, что новых периодов не будет, если все периоды по лимиту уже созданы.
- Возобновление:
  - у прекращённого платежа в списке и карточке «Возобновить»;
  - в окне выбор: «По прежнему расписанию» или «С другой даты» (не раньше сегодня). Если до выбранного срока осталось не больше окна напоминания, окно предупреждает, что напоминание уйдёт сразу;
  - после возобновления платёж снова действующий, всплывающее уведомление называет ближайший срок;
  - `409 payment_active` - платёж уже действует: окно закрывается, данные перечитываются.
- Окно прекращения называет периодичность платежа, а не всегда «ежемесячно». Вместо «Вернуть платёж нельзя» оно говорит, что платёж можно будет возобновить.
- Порядок вариантов периодичности: «Еженедельно», «Раз в две недели», «Ежемесячно» (по умолчанию), «Раз в квартал», «Раз в полгода», «Ежегодно», «Другая периодичность».

Вне изменения:
- отдельный фильтр «Завершённые»: сервер считает завершённый платёж действующим, он виден в «Действующих»;
- прогноз в бюджете и календаре: его считает сервер;
- правка контракта API.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities
- `web-recurring-payments`: число оплат в форме, списке и карточке, возобновление прекращённого платежа, порядок вариантов периодичности, тексты окна прекращения.

## Impact

- Часть репо: `frontend/`. Затронуты:
  - `src/features/recurring-payment-form`;
  - `src/entities/recurring-payment`;
  - `src/pages/recurring-payments`;
  - тесты `src/app/recurring-payments.test.tsx`, `frontend/plan.md`.
- Клиент API уже перегенерирован по контракту dev (`e1c5be1`). Контракт `backend/api/openapi.yaml` здесь не меняется.
