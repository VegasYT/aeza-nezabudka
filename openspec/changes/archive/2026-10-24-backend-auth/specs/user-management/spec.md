# Spec Delta

## Purpose

Учётные записи системы: администратор из `.env` и обычные пользователи, которых заводит администратор. Пользователи и пароли хранятся в Keycloak (ADR-005, ADR-008).

## ADDED Requirements

### Requirement: Администратор из настроек
При каждом запуске `api` пользователь с логином `ADMIN_LOGIN` SHALL существовать в Keycloak, быть включён, иметь пароль `ADMIN_PASSWORD` и роль `admin`. Если логин в настройках сменили, прежний администратор из настроек SHALL быть отключён и лишён роли `admin`.

#### Scenario: Первый запуск
- **WHEN** `api` запускается, а пользователя `ADMIN_LOGIN` в Keycloak нет
- **THEN** он создаётся с паролем из настроек и ролью `admin` и может войти

#### Scenario: Пароль изменён в настройках
- **WHEN** `ADMIN_PASSWORD` изменили и `api` перезапустили
- **THEN** администратор входит с новым паролем

#### Scenario: Логин изменён в настройках
- **WHEN** `ADMIN_LOGIN` сменили с `admin` на `chief` и `api` перезапустили
- **THEN** `chief` - администратор, `admin` отключён и без роли `admin`

#### Scenario: Повторный запуск
- **WHEN** `api` перезапускается без изменения настроек
- **THEN** ничего не меняется и пользователи не дублируются

### Requirement: Список пользователей
`GET /users` SHALL возвращать пользователей с ролью `user` без администраторов, с логином, признаком включения и временем создания, по алфавиту логина, страницами.

#### Scenario: Список
- **WHEN** в системе администратор и два пользователя, администратор запрашивает `GET /users`
- **THEN** в ответе два пользователя, `total` равен 2

### Requirement: Создание пользователя
`POST /users` SHALL создавать включённого пользователя с ролью `user` и указанным паролем; пользователь SHALL сразу мочь войти без дополнительных действий. Занятый логин SHALL давать 409 `login_taken`. Пароль, который не прошёл политику паролей Keycloak, SHALL давать 422 с полем `password`.

#### Scenario: Новый пользователь
- **WHEN** администратор создаёт пользователя `buh.petrova` с паролем из 8 и более символов
- **THEN** ответ 201 с пользователем, он входит с этим паролем и получает роль `user`

#### Scenario: Логин занят
- **WHEN** пользователь `buh.petrova` уже есть
- **THEN** ответ 409 `login_taken`

### Requirement: Изменение пользователя
`PATCH /users/{id}` SHALL менять пароль и признак включения. Смена пароля и отключение SHALL завершать все сессии пользователя в Keycloak.

#### Scenario: Отключение
- **WHEN** администратор отключает пользователя
- **THEN** пользователь не может войти и не может обновить уже полученный токен

#### Scenario: Смена пароля
- **WHEN** администратор меняет пароль пользователя
- **THEN** старый пароль не подходит, новый подходит, прежние сессии завершены

#### Scenario: Несуществующий пользователь
- **WHEN** идентификатора нет в Keycloak
- **THEN** ответ 404 `user_not_found`

### Requirement: Удаление пользователя
`DELETE /users/{id}` SHALL удалять пользователя из Keycloak вместе с его сессиями.

#### Scenario: Удаление
- **WHEN** администратор удаляет пользователя
- **THEN** ответ 204, пользователь не может войти и пропадает из списка

### Requirement: Администраторы не меняются через API
Изменение и удаление пользователя с ролью `admin` через `/users` SHALL давать 409 `admin_protected`.

#### Scenario: Попытка удалить администратора
- **WHEN** администратор вызывает `DELETE /users/{id}` для пользователя с ролью `admin`, в том числе для себя
- **THEN** ответ 409 `admin_protected`, пользователь не меняется

### Requirement: Keycloak недоступен
Если Keycloak не отвечает, операции `/users` SHALL давать 503 `identity_unavailable`.

#### Scenario: Сбой Keycloak
- **WHEN** Keycloak недоступен и администратор вызывает `GET /users`
- **THEN** ответ 503 `identity_unavailable`
