# Proposal

## Why

Оплату отмечают из панели, кнопкой в Telegram и через API, а открытая панель узнаёт об этом только при следующем запросе. Привязку Telegram панель ждёт опросом сервера раз в 3 секунды. Backend отдаёт поток событий `GET /api/v1/events` (ADR-016): по нему панель может обновляться сразу.

## What Changes

- После входа вкладка держит один поток событий; закрывает его при выходе и пока вкладка скрыта.
- Поток переподключается сам: после закрытия сервером (раз в 10 минут и после события о самом участнике) и после обрыва, с растущей паузой. Ответ 401 открывает окно повторного входа, после входа поток подключается снова.
- По событию `change` панель перечитывает затронутые данные: платежи, периоды, итоги и прогноз; отделы; участников и свой профиль; личный Telegram; групповые чаты; журнал.
- После переподключения и по `resync` панель перечитывает все данные: события за время обрыва потеряны.
- Отметку оплаты другим участником (в панели или кнопкой в Telegram) панель показывает уведомлением.
- Ожидание привязки личного Telegram и группы закрывается по событию; опрос раз в 3 секунды остаётся только на время, пока потока нет.
- Клиент API перегенерирован (`pnpm api:generate`): в контракте появилась операция `stream_events`.

## Capabilities

### New Capabilities

- `web-live-updates`: поток событий в панели и обновление данных по нему.

### Modified Capabilities

- `web-notifications`: ожидание привязки по событию вместо постоянного опроса.

## Impact

- `frontend/src/shared/live`: подключение к потоку и его состояние.
- `frontend/src/app`: разбор событий и перечитывание запросов, уведомление об оплате.
- `frontend/src/pages/notifications/model/use-link-flow.ts`: опрос только без потока.
- Новых зависимостей нет: поток читает сгенерированная функция `streamEvents` (Hey API, `fetch` с заголовком `Authorization`).
