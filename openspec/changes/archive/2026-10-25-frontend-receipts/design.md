# Design

## Context

Чек - один файл у оплаченного периода: `PUT /payment-occurrences/{id}/receipt` (multipart, поле `file`), `GET` отдаёт файл, `DELETE` удаляет. У периода поле `receipt` (`fileName`, `contentType`, `size`, `uploadedAt`, `uploadedByLogin`), в `GET /settings` - `receiptsEnabled`. Отмена оплаты удаляет чек на сервере.

## Decisions

- **Файл - через сгенерированный `getReceipt` (axios, `responseType: 'blob'`).** Запрос несёт токен сессии и повторный вход на 401, как все. `blob:`-ссылку создаёт и отзывает хук на время показа окна.
- **PDF - кнопкой в окне чека, а не сразу по нажатию.** Вкладку, открытую после ожидания запроса, браузеры блокируют как всплывающее окно. Окно чека сначала скачивает файл, «Открыть PDF» открывает уже готовую ссылку в ответ на нажатие.
- **Одно окно чека для просмотра и загрузки.** Без чека оно предлагает выбрать файл, с чеком - показывает его, «Заменить» и «Удалить». Так «Приложить чек» из меню и кнопка «Чек» ведут в одно место.
- **Чек в окне даты - только у «Оплачено в другой день».** «Оплачено» остаётся одним нажатием; чек к нему прикладывается из меню. «Исправить дату» - про дату, чек там лишний.
- **Включение - обработчиком.** `onReceipt` в `OccurrenceHandlers` есть, только если `receiptsEnabled`; таблица, карточки, меню и лист показывают чеки по нему, без отдельного флага.
- **Подтверждение отмены - только с чеком.** Без чека отмена по-прежнему в одно нажатие с «Вернуть»; чек «Вернуть» не восстановит, поэтому о нём предупреждаем заранее.
- **Проверка файла до отправки** - тип по MIME или расширению и размер; окончательно тип по содержимому проверяет сервер.

## Risks / Trade-offs

- «Вернуть» после отмены оплаты с чеком отмечает оплату без чека: файл удалён на сервере.
