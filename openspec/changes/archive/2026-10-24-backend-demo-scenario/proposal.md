# Proposal

## Why

Основа тестовых данных сделана до отделов (шаг 11, основа). Теперь отделы есть, и фильтр по ним на защите нечем показать. Сценарий защиты (раздел 14 `docs/plan.md`) проверяется руками; перед сдачей нужен скрипт, который за минуту пройдёт его через API и скажет, какой шаг сломался. Это дополнение шага 11 `backend/plan.md`.

## What Changes

- Сид создаёт отделы "Офис" и "ИТ" и раскладывает по ним платежи; повторный запуск отделы не дублирует.
- Команда `uv run python -m app.smoke`: получает токен сервисной учётной записи (client credentials) и проходит сценарий защиты через API: готовность, создание платежа в окне напоминания с `Idempotency-Key`, отметка оплаты, следующий период, просроченный период и исправление даты, итоги по валютам. Изменения в демо-данных она возвращает обратно, созданный платёж прекращает.

Вне изменения:

- клиент Keycloak с ролью `integration` для smoke и демо встраивания, запуск в compose - этап "Фундамент" (infra); до него команде передаются адрес токена, идентификатор и секрет клиента;
- шаги сценария, которые проверяются только глазами (Telegram, Grafana), smoke не проверяет.

## Capabilities

### New Capabilities

- `smoke-check`: что проверяет smoke-скрипт и как сообщает о сбое.

### Modified Capabilities

- `demo-data`: в тестовых данных появляются отделы.

## Impact

- `backend/app/seed.py`, `backend/app/smoke.py`, тесты, `backend/AGENTS.md`, `backend/plan.md`.
- Контракт API не меняется.
