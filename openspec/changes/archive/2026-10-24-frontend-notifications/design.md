# Design

## Context

Мотивация - в proposal.md. Контракт готов: `GET/PATCH/DELETE /me/telegram`, `POST /me/telegram/link`, `GET /telegram-chats`, `POST /telegram-chats/link`, `PATCH/DELETE /telegram-chats/{chat_id}`; клиент, опции запросов и обработчики MSW уже сгенерированы. Макеты - холст, доски `Notif*`, `NotifAdmin*`, `NotifMyDepts`. Проверено по коду backend:

- после `/start <код>` привязка сразу `personalEnabled = true`, `blocked = false`; повторная привязка заблокированного снимает блокировку;
- пустой фильтр отделов (все отделы удалены) сервер отдаёт как `departmentIds: null`, у личного фильтра и у группы;
- повторное подключение группы по ссылке ставит новое `linkedAt`, снимает `blocked` и сохраняет её отделы;
- `GET /departments` доступен всем ролям, `/telegram-chats` - только администратору.

## Goals / Non-Goals

**Goals:** один механизм ссылки и ожидания для личного Telegram и групп; окно выбора отделов общее для личного фильтра и групп; тесты сценариев на MSW.

**Non-Goals:** WebSocket или push о привязке (только перечитывание), своя страница для групп (решено с пользователем: блок в «Уведомлениях»).

## Decisions

### Слайс страницы

Весь код в `src/pages/notifications`: `model/` (запросы, ссылка и ожидание, тексты ошибок), `lib/` (подписи отделов, образцы напоминаний), `ui/` (страница, острова, окна, шаги подключения, QR). В слои ниже уходит только то, что нужно другим страницам (форматирование моментов). Значок внешней ссылки - в `@shared/ui/icons`, в конец файла.

### Ссылка и ожидание: общий хук

`useTelegramLink({ create, done })` держит полученную ссылку, ошибку и признак «устарела». Время окончания - `expiresAt` с сервера; таймер до него переключает «устарела» и останавливает ожидание. Пока ссылка действует, запрос состояния (`GET /me/telegram` или `GET /telegram-chats`) получает `refetchInterval` 3 секунды; при возврате на вкладку его перечитывает TanStack Query сам. Ожидание заканчивается условием `done`:

- личный Telegram - `linked && !blocked`;
- группа - по снимку списка в момент получения ссылки: появилась новая группа, у группы сменилось `linkedAt` или у восстанавливаемой группы пропала блокировка.

Альтернатива - сравнивать `linkedAt` со временем выдачи ссылки. Отвергнута: время выдачи пришлось бы выводить из `expiresAt` минус 10 минут, а это знание о настройке сервера.

«Открыть Telegram» - обычная ссылка `<a target="_blank" rel="noopener noreferrer">`, без перехода из скрипта: так её не блокирует браузер и её можно скопировать.

### QR-код: `uqr`

`encode(url, { ecc: 'M', border: 2 })` отдаёт матрицу; рисуем её одним `<path>` в SVG. Цвета - белый фон и чёрные модули (`--mantine-color-white`, `--mantine-color-black`) в обеих схемах: тёмный код на светлом фоне читают все камеры. Альтернативы: `qrcode` тянет `pngjs` и `yargs`, `qrcode.react` - обёртка над тем же с меньшим контролем стилей. `uqr` без зависимостей, бандл работает без интернета. Решение выведено из задачи, пользователь выбрал только сам QR-код.

### Окно «Какие платежи присылать»

Один компонент для личного фильтра и группы: подпись («вам лично в Telegram» или «в группу «…»»), начальный `departmentIds`, `onSave(departmentIds | null)`. Отделы - `listDepartmentsOptions({ query: { limit: 100 } })`; ключ запроса совпадает с разделом «Отделы», кэш общий. Допущение (в макете нет): если отделов нет, вариант «Только выбранных отделов» недоступен с подписью «отделов пока нет». Отделы фильтра, которых нет в справочнике (удалили между запросами), в подписи пропускаются.

### Запись и обновление состояния

- `PATCH /me/telegram` отдаёт новое состояние: кладём его в кэш (`setQueryData`), без лишнего запроса.
- Переключатель не оптимистичный: пока запрос идёт, показывает отправленное значение; при ошибке возвращается к данным кэша, ошибка - уведомлением Mantine с постоянным `id` (сначала `hide`).
- `DELETE /me/telegram`, запись и удаление групп - перечитывание затронутого запроса.
- Ответы «объекта нет»: `409 telegram_not_linked` (отвязали в другой вкладке или командой `/stop`) и `404` группы - текст ошибки в окне и перечитывание состояния; `400` по отделам - текст сервера в окне и перечитывание отделов.

### Настройки сервера

Окно напоминания (`reminderDaysBefore`) и «сегодня» для образцов - из `settingsOptions()`. Маршрут `/notifications` ждёт их в `loader`, как «Платежи», страница читает `useSuspenseQuery`. Образцы повторяют формат сообщения бота (`backend/apps/reminders/domain.py`, `reminder_text`): «Напоминание: до срока оплаты 3 дня. Сервер (ИТ) - 25,00 USD, срок 27.10.2026» и «Просрочена оплата: …, срок был …»; суммы в формате бота (код валюты), даты от «сегодня» сервера.

### Моменты времени в `@shared/lib/dates`

`formatDate` и `formatDateTime` из `pages/users/lib/format.ts` переезжают в `@shared/lib/dates/moment.ts` как `formatMoment` и `formatMomentTime`, рядом `formatTimeOfDay` («14:32» для срока ссылки). Теперь они нужны двум страницам; календарный `formatDate` (`YYYY-MM-DD`) не трогаем: момент и календарная дата - разные типы. «Пользователи» импортируют из shared, их тесты форматов переезжают вместе с функциями.

### Раскладка

Две колонки на flex с переносом, как в макете: слева «Личный Telegram» и у администратора «Групповые чаты», справа «Общий и групповые чаты» и «Как выглядят напоминания». На узком экране колонки встают друг под другом. Таблица групп или карточки и показ QR-кода выбираются `useMatches` по `sm`, как в других разделах.

### Тесты

Сценарии через `renderApp('/notifications')` в `src/app/notifications.test.tsx`: роль из `signIn(role)` проверяет показ групп только администратору, а маршрут - загрузку настроек. «Сервер» в тестах - обработчики MSW с состоянием (привязка, список групп). Ожидание привязки проверяется поддельными таймерами (`vi.useFakeTimers({ shouldAdvanceTime: true })`). Тестам, которые открывают `/notifications` (`routes`, `app-layout`, `reauth`), нужен `serveNotificationsScreen()` из `test-utils/notifications-mocks.ts`: отдельный файл, чтобы правки `api-mocks.ts` параллельных change не сталкивались в импортах.

## Risks / Trade-offs

- [Перечитывание раз в 3 секунды до 10 минут] → только пока ссылка действует и вкладка видима (`refetchIntervalInBackground` выключен); возврат на вкладку перечитывает сразу.
- [Группы без пагинации: первые 100] → у одной компании групп единицы; предел API тот же.
- [Пользователь закрыл вкладку во время ожидания] → ссылка остаётся рабочей, привязка видна при следующем открытии раздела.
