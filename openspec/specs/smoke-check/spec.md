# smoke-check Specification

## Purpose
Быстрая проверка сценария защиты через API перед сдачей: прошёл ли он целиком и на каком шаге сломался.

## Requirements

### Requirement: Сценарий защиты через API
Команда `python -m app.smoke` SHALL ходить в API с `X-API-KEY` аккаунта Aéza из переменной `SMOKE_API_KEY` (участник с ролью `integration` или `admin`) и по порядку проверять сценарий защиты: готовность сервиса, создание платежа в окне напоминания с `Idempotency-Key`, отметку оплаты, исправление даты оплаты, отдельный статус следующего периода и итоги по трём валютам. Команда SHALL завершаться кодом 0, если все шаги прошли.

#### Scenario: Стенд исправен
- **WHEN** стенд запущен, сид выполнен, аккаунт ключа в белом списке
- **THEN** все шаги проходят, код выхода 0

#### Scenario: Ключ не в белом списке
- **WHEN** аккаунт ключа не добавлен в белый список
- **THEN** команда завершается кодом 1 на первом шаге с API и сообщает 403 `not_a_member`

### Requirement: Сообщение о сбое
На первом неудачном шаге команда SHALL останавливаться с кодом 1 и выводить номер и название шага, код ответа и тело ответа API. Ключ `SMOKE_API_KEY` SHALL не выводиться.

#### Scenario: Нет просроченного периода
- **WHEN** сид не выполнялся и просроченных периодов нет
- **THEN** команда завершается кодом 1 с названием шага про просрочку

### Requirement: Демо-данные не портятся
Команда SHALL возвращать изменённые ей демо-данные в исходное состояние и прекращать созданный ей платёж, чтобы повторный запуск и защита видели те же данные.

#### Scenario: После smoke
- **WHEN** smoke прошёл
- **THEN** просроченный период сида снова просрочен, платёж smoke прекращён
